# 时变场景快速学习智能体技术说明

## 1. 文档概述

本文说明本项目面向“用于时变场景的快速学习智能体”比赛方案所实现的场景路由目标检测系统，内容包括：

- 智能体总体结构与模型间的信息传递；
- 场景分类器、easy 六分类检测器、hard 三分类检测器的网络结构；
- 四类到六类的增量学习训练逻辑；
- 森林/城市困难场景的高分辨率识别策略；
- ONNX 部署接口、后处理和昇腾 310B 适配路径；
- 验证集、指标定义、实验结果和当前能力边界。

当前文档对应的部署方案为“三模型互斥路由”：每张图片先经过场景分类器，再根据场景选择 easy 或 hard 检测器，单张图片只执行一个检测分支。

## 2. 与赛题要求的对应关系

比赛方案要求系统至少包含三个不同功能模型，并完成场景理解、策略决策、目标检测识别、增量学习和端侧部署。本项目的对应关系如下：

| 赛题功能 | 本项目实现 | 输入/输出 |
|---|---|---|
| 场景认知 | YOLOv8n-cls 四场景分类器 | 图像 -> `air/forest/sea/urban` 及置信度 |
| 任务决策 | 规则化场景路由器 | 场景结果 -> `easy` 或 `hard` |
| 目标检测识别 | YOLOv10n 六分类检测器、YOLOv8n hard 三分类检测器 | 图像 -> 统一六分类目标框 |
| 增量学习 | 场景分类器 r1+r2 增量微调、检测器四类到六类迁移 | 新数据 -> 更新 checkpoint |
| 端侧部署 | ONNX batch=1 模型包和统一推理接口 | ONNX -> 运行结果 JSON |
| 反馈闭环 | Agent 推理记录、人工反馈和 replay 清单 | 结果/反馈 -> 后续训练输入 |

### 2.1 当前实现边界

当前三模型 ONNX 的实际张量输入是图像张量。Agent 接口支持 `ir`、`sar` 和 `unknown` 传感器字段，传感器字段用于记录和策略接口兼容，但当前版本尚未将雷达与红外做像素级或特征级联合编码。因此文档中将“多模态接口支持”和“多模态特征融合”区分描述：前者已具备，后者属于后续扩展项。

仓库中的 `Agent/` 目录目前默认绑定早期四分类交付包，默认类别和部分 ONNX 输出形状仍是旧版本口径；本文的三模型六分类方案以 `ChallengeCup-agent-soldier-route/route_inference.py` 和 `route_3onnx_best_20260829/` 为准。将当前三模型包接入 `Agent/` 统一入口时，需要同步更新 `Agent/config.py` 中的类别列表、模型相对路径、输入输出形状和模型清单校验，不能直接复用旧四分类 manifest。

## 3. 系统总体架构

```text
                  图像 + 可选传感器提示
                           │
                           ▼
             场景认知模型：YOLOv8n-cls 224
                 输出 scene_id, scene_conf
                           │
             ┌─────────────┴─────────────┐
             │                           │
       air / sea                    forest / urban
       conf >= 0.60                或 conf < 0.60
             │                           │
             ▼                           ▼
   easy 六分类 YOLOv10n          hard 三分类 YOLOv8n
       输入 640×640                   输入 960×960
             │                           │
             └─────────────┬─────────────┘
                           ▼
                统一六分类检测结果 JSON
                           │
                           ▼
                 一致性诊断、耗时记录、反馈 replay
```

路由器同时承担轻量任务决策功能。它不修改检测框，也不通过验证集标签替换预测结果；它只决定本张图使用哪个检测模型。

## 4. 三个核心模型

### 4.1 场景分类模型

文件：`scene_classifier_r1r2_route_safe_224.onnx`

模型为 YOLOv8n-cls 分类网络，采用 YOLOv8 的轻量卷积骨干和分类头。网络使用多级卷积下采样、C2f 特征提取模块，末端通过 Classify 分类头输出四个场景的 logits/probabilities。实际 checkpoint 约含1.44M参数、10个主模块层。

| 项目 | 配置 |
|---|---|
| 任务 | 四分类图像分类 |
| 场景顺序 | `air, forest, sea, urban` |
| 参数量 | 约 1.44M |
| 输入 | `[1,3,224,224]`，RGB、float32 |
| 输出 | `[1,4]` |
| ONNX opset | 12 |
| batch | 1 |
| 作用 | 生成场景标签和路由置信度 |

场景分类的最高分为 `scene_confidence`。它与检测目标的置信度是两个不同概念，不能混用。

### 4.2 easy 六分类检测模型

文件：`detector_6class_640.onnx`

该模型来自四类基础检测模型到六类目标的增量迁移，采用 YOLOv10n 检测结构。骨干网络由卷积、SCDown、C2f、SPPF 和 PSA 模块组成，颈部通过 Upsample、Concat 和 C2f/C2fCIB 完成三尺度特征融合，末端使用 `v10Detect` 头输出端到端检测结果。实际 checkpoint 约含2.71M参数、24个主模块层。模型训练口径为 960×960，部署导出为 640×640，以降低空中和海面场景的推理开销。

| 项目 | 配置 |
|---|---|
| 任务 | 六类目标检测 |
| 参数量 | 约 2.71M |
| 训练尺寸 | 960×960 |
| 部署尺寸 | 640×640 |
| 输入 | `[1,3,640,640]` |
| 输出 | `[1,300,6]` |
| 检测头 | YOLOv10 端到端检测头 |
| 类别顺序 | `soldier, small_aircraft, warship, tank, patrol_boat, armored_vehicle` |

每个输出候选按 `[x1,y1,x2,y2,confidence,class_id]` 解析。模型输出已包含最终六分类编号，easy 分支不需要再做类别映射。

### 4.3 hard 三分类检测模型

文件：`hard_3class_corrected_960.onnx`

该模型针对森林和城市中的小目标、遮挡和复杂背景训练，保留 `soldier`、`tank`、`armored_vehicle` 三类。采用 COCO 预训练 YOLOv8n 的轻量卷积骨干，使用 C2f、SPPF 和三尺度 PAN/FPN 特征融合，末端使用标准 `Detect` 头，在困难场景子集上重新训练，并固定使用 960×960 方形训练。实际 checkpoint 约含3.01M参数、23个主模块层。

| 项目 | 配置 |
|---|---|
| 任务 | 困难陆地场景三类检测 |
| 参数量 | 约 3.01M |
| 输入 | `[1,3,960,960]` |
| 输出 | `[1,7,18900]` |
| 检测头 | YOLOv8 Detect 原始检测头 |
| 类别顺序 | `soldier, tank, armored_vehicle` |
| ONNX opset | 12 |

YOLOv8 原始检测头输出需要解码、置信度过滤和 NMS。hard 局部类别必须映射回系统六分类编号：

| hard 局部编号 | 类别 | 全局六分类编号 |
|---:|---|---:|
| 0 | soldier | 0 |
| 1 | tank | 3 |
| 2 | armored_vehicle | 5 |

## 5. 场景路由和任务决策

### 5.1 路由规则

场景分类器输出四类概率后，取最高概率类别：

```python
scene_id = argmax(scene_scores)
scene_confidence = max(scene_scores)
```

路由阈值为 `0.60`：

```python
if scene_confidence < 0.60:
    route = "hard"
elif scene_id in (0, 2):       # air, sea
    route = "easy"
else:                          # forest, urban
    route = "hard"
```

因此只有“高置信度 air/sea”进入低分辨率 easy 分支；forest、urban 和所有不确定样本进入高分辨率 hard 分支。

### 5.2 安全回退设计

低置信度样本进入 hard 是保护 soldier 召回率的安全策略。场景分类器若在 easy/hard 两组之间犹豫，将图像送入 hard 的代价是计算量增加，但不会把森林或城市小目标交给较低分辨率分支。

在当前183张原始验证图上，选定的 route-safe 场景 checkpoint 有一张 hard 图的原始预测最高分约为 `0.589`，由于低于 `0.60`，实际被回退到 hard。按有效路由组统计，easy/hard 路由准确率达到100%。

### 5.3 路由不做场景内过度屏蔽

easy 分支保留六分类输出，避免错误的场景细分类规则屏蔽新增类别。hard 分支虽然只产生三类，但通过编号映射后仍输出统一六分类格式。路由只改变检测器和输入尺寸，不使用验证集标签替代模型预测。

## 6. 数据组织与数据预处理

### 6.1 六分类增量数据

六分类检测数据配置为：

- 训练集：`D:/yolo_r1_r2inc_augmented_full/yolo_r1_r2inc_augmented_full/images/train`；
- 验证集：同一数据集的 `images/val`；
- 类别：六类目标；
- 训练图像：2828张；
- 原始验证图像：183张。

最终验证口径使用183张原始图，不将增广图复制到验证集，也不将验证图重新放回训练集。

### 6.2 hard 三分类数据

hard 数据集由森林和城市困难场景筛选生成，并将六分类标签映射为三分类标签：

```text
原类别 0 soldier          -> hard 类别 0 soldier
原类别 3 tank              -> hard 类别 1 tank
原类别 5 armored_vehicle   -> hard 类别 2 armored_vehicle
```

当前数据统计：

| split | 图像数 | 标注框数 |
|---|---:|---:|
| train | 1508 | 6652 |
| val（原图） | 99 | 410 |

图像采用硬链接或复制方式生成数据集副本，标签只保留三类目标。hard 验证集不包含训练增广图。

### 6.3 场景分类数据

场景分类器使用 r1+r2 增量场景数据，目录遵循 Ultralytics 分类格式：

```text
scene_cls_r1_r2_incremental/
├── train/
│   ├── air/
│   ├── forest/
│   ├── sea/
│   └── urban/
└── val/
    ├── air/
    ├── forest/
    ├── sea/
    └── urban/
```

路由评估仍回到目标检测的183张原始验证图上，以测量“场景分类错误是否真正跨越 easy/hard 分组”。这比单独统计四分类 Top-1 更符合路由任务目标。

### 6.4 图像预处理

1. 读取图像并由 BGR 转换为 RGB；
2. 场景分类器保持宽高比，将短边缩放到 224，再做 224×224 中心裁剪；
3. easy/hard 检测器保持宽高比，分别 letterbox 到 640×640 和 960×960，填充值为 114；
4. 转换为 NCHW float32，并把像素值归一化到 `[0,1]`；
5. 检测框经过逆 letterbox 变换还原到原图坐标系；
6. 坐标裁剪到原图边界。

分类器的“短边缩放 + 中心裁剪”不能替换成检测器 letterbox 或直接拉伸。真实验证图抽查中，该分类前处理下 PyTorch 与 ONNX 四类概率最大绝对差约 `9.2e-9`。easy/hard 检测器则必须保留各自的 letterbox 和逆变换。

## 7. 训练逻辑

### 7.1 场景分类器增量训练

训练入口：`scene_recognition/route_training/train_scene_router_incremental.py`

训练流程：

1. 加载已有四场景 YOLOv8n-cls checkpoint；
2. 将 r1 与 r2 场景样本合并到统一分类目录；
3. 保留 `air/forest/sea/urban` 四个输出类别；
4. 以224×224、batch32进行微调；
5. 使用 `optimizer=auto`、cosine learning rate、AMP 和固定随机种子42；
6. 保存中间 checkpoint；
7. 不只按普通 Top-1 选择模型，而是在目标检测验证图上检查跨组路由错误；
8. 选择 route-safe checkpoint 并导出 ONNX。

训练参数：

```text
epochs=50, patience=10, imgsz=224, batch=32
workers=2, seed=42, deterministic=True
optimizer=auto, cos_lr=True, amp=True
```

选择 route-safe checkpoint 的原因是：air 与 sea 都属于 easy，forest 与 urban 都属于 hard。同组场景互相误判不会改变检测分支，而跨组误判会改变检测分支，因此路由安全性比单一 Top-1 更重要。

### 7.2 easy 六分类增量训练

训练入口：`scene_recognition/route_training/train_easy_6class_yolov10_incremental.py`

训练流程：

1. 从四类 YOLOv10n 迁移 checkpoint `init6.pt` 开始；
2. 将检测头调整为六类，保留可迁移的基础特征；
3. 使用2828张六分类训练图进行增量微调；
4. 训练尺寸保持960×960，与历史六分类增量模型训练口径一致；
5. 训练结束后选择 `best.pt`；
6. 以640×640、batch1、opset12导出 easy ONNX。

训练参数：

```text
epochs=50, patience=20, imgsz=960, batch=8
workers=2, seed=42, cos_lr=True, device=0
```

旧类别样本继续保留在训练数据中，避免只注入新增类别导致旧知识快速丢失。新增类别为 `patrol_boat` 和 `armored_vehicle`，最终模型保持六类统一输出。

### 7.3 hard 三分类高分辨率训练

训练入口：`scene_recognition/route_training/train_hard_3class_yolov8n_corrected.py`

训练流程：

1. 加载 COCO 预训练 YOLOv8n；
2. 使用hard数据集的森林/城市样本；
3. 将目标类别压缩为 soldier、tank、armored_vehicle三类；
4. 使用960×960方形训练；
5. 开启 Mosaic、shuffle、AMP 和 cosine learning rate；
6. 末尾10个epoch关闭 Mosaic，稳定收敛；
7. 保存 best/last checkpoint，并在独立原图验证集上评估；
8. 导出960×960 hard ONNX。

训练参数：

```text
epochs=150, patience=20, imgsz=960, batch=8
workers=2, seed=42, deterministic=True
optimizer=auto, rect=False, mosaic=1.0
close_mosaic=10, cos_lr=True, amp=True
```

此前的 hard 实验曾使用 `rect=True`、关闭 Mosaic 和关闭 shuffle，结果明显变差。修正版恢复与有效基线一致的增强和采样策略，矩形尺寸只作为推理对照，不作为训练方式。

## 8. 增量学习与抗遗忘逻辑

### 8.1 检测器类别增量

基础阶段模型已学习四类目标。第二轮注入 `patrol_boat` 和 `armored_vehicle` 后，构造六类检测头并迁移原有特征。训练集同时包含旧类别和新类别，验证集评估全部已学习类别：

```text
旧类别：soldier, small_aircraft, warship, tank
新类别：patrol_boat, armored_vehicle
```

该方式的核心是“旧知识样本回放 + 新类别头扩展”，而不是只使用新增类别进行训练。当前版本未加入蒸馏、EWC 等额外抗遗忘损失，旧类保持主要依靠混合训练数据和稳定的微调参数。

### 8.2 场景分类器增量

场景分类器从已有 r1 checkpoint 继续训练 r1+r2 数据，使路由器获得第二轮场景样本分布。训练过程中保存多个 checkpoint，并根据最终 easy/hard 路由错误选择安全 checkpoint。

### 8.3 反馈闭环

Agent 会记录：原始场景、场景置信度、最终路由、检测结果、耗时和模型校验信息。人工反馈可写入 replay 清单，后续训练程序可使用这些修正样本。当前 replay 是训练数据导出机制，尚未实现在线反向传播和自动替换生产模型。

## 9. 推理与后处理

### 9.1 伪代码

```python
scene_scores = scene_router(image_224)
scene_id = argmax(scene_scores)
scene_conf = max(scene_scores)

if scene_conf < 0.60 or scene_id in (1, 3):
    raw = hard_detector(letterbox(image, 960, 960))
    detections = decode_yolov8(raw)
    detections = confidence_filter_and_nms(detections)
    detections = remap_hard_ids(detections, {0: 0, 1: 3, 2: 5})
else:
    raw = easy_detector(letterbox(image, 640, 640))
    detections = parse_yolov10_end2end(raw)
    detections = confidence_filter(detections)

return unified_result(scene_id, scene_conf, detections)
```

### 9.2 两种检测头的差异

easy YOLOv10输出已经是端到端候选框，主要进行置信度过滤和坐标还原。hard YOLOv8输出是原始检测头张量，需要进行框解码、类别分数计算、置信度过滤、class-aware NMS和类别映射。两条分支不能直接共用完全相同的后处理代码。

### 9.3 统一输出格式

```json
{
  "class_id": 0,
  "class_name": "soldier",
  "confidence": 0.73,
  "bbox_xyxy": [x1, y1, x2, y2]
}
```

完整推理报告还包含：

- `scene.label` 和 `scene.confidence`；
- `final_scene`，低于阈值时标记为 `uncertain`；
- `routing.route` 和 `routing.reason`；
- 检测器输入尺寸；
- 目标数量、冲突诊断和总耗时；
- 模型包路径和 SHA-256 校验结果。

## 10. ONNX 与昇腾 310B 部署方案

### 10.1 当前 ONNX 接口

| 模型 | 输入 | 输出 | opset | 部署用途 |
|---|---|---|---:|---|
| scene router | `[1,3,224,224]` | `[1,4]` | 12 | 场景认知 |
| easy detector | `[1,3,640,640]` | `[1,300,6]` | 12 | air/sea |
| hard detector | `[1,3,960,960]` | `[1,7,18900]` | 12 | forest/urban/不确定 |

三个模型均为 batch=1，便于端侧固定内存和静态图优化。部署包中同时提供 `route_config.yaml`、类别映射和 SHA-256 文件。

### 10.2 310B 适配路径

目标平台为华为昇腾 310B，推荐部署流程为：

1. 在 x86 环境使用 ONNX checker 验证模型结构；
2. 使用 CANN `atc` 将 ONNX 转换为 OM；
3. 固定 batch=1 和输入 shape，减少动态 shape 开销；
4. 在 310B 上分别验证三模型输出与 PyTorch/ONNX 输出的一致性；
5. 将场景路由、预处理、后处理和三个 OM 串成端到端程序；
6. 测量单帧端到端 FPS、峰值内存和各阶段耗时。

当前仓库已完成 ONNX 导出、结构检查、接口定义和 CPU/CUDA 推理封装；昇腾 OM 转换及实机 FPS 需要在具备 310B 和 CANN 的环境中完成，本文不将其标记为已实测结果。

## 11. 实验结果

评估集为六分类数据集固定的183张原始验证图，不包含增广图。当前三模型互斥路由结果如下：

| 指标 | 结果 |
|---|---:|
| 场景分类原始 Top-1 | 约95.08% |
| easy/hard 有效路由准确率 | 100% |
| soldier AP50 | 71.40% |
| 六分类 mAP50 | 92.14% |
| 六分类 mAP50-95 | 46.23% |
| easy 图像数 | 84 |
| hard/回退图像数 | 99 |
| 平均计算量（含分类器） | 约14.24 GFLOPs/图 |

hard 三分类模型在其自身三类验证口径上的代表性结果为：

| 类别 | AP50 |
|---|---:|
| soldier | 约69.20% |

## 12. 方案对比与选择

| 方案 | soldier AP50 | 六类 mAP50 | 计算特点 | 结论 |
|---|---:|---:|---|---|
| 全部六类模型 960 | 61.76% | 89.84% | 单模型、开销稳定 | 基线 |
| easy/hard 互斥路由 | 约71.40% | 约92.14% | 每图只跑一个检测器 | 当前部署方案 |
| hard 双分辨率融合 | 约64.99% | 约90.38% | hard 图需多次检测 | 精度对照，不部署 |
| 三层 soldier 专家融合 | 约69.83% | 约91.18% | 计算量和后处理复杂 | 历史实验 |
| 六类 + 旧四类 soldier 双检测 | 约70.41% | 约91.28% | 需额外旧模型 | 历史实验 |

最终选择互斥路由，原因是它在保持较高 soldier 指标的同时，避免每张图运行多个检测器，部署链路更短、输出更容易解释、平均计算量更低。

## 15. 结论

本项目形成了一个由场景认知、策略路由和目标检测组成的轻量多模型协同系统。训练阶段通过场景分类器增量微调和四类到六类检测器迁移实现新类别适应，通过hard三分类高分辨率模型处理森林/城市中的小目标；推理阶段通过0.60安全阈值将不确定样本回退至hard分支，并将两个检测分支统一为六分类输出。

当前版本已经具备可复现训练代码、ONNX模型接口、路由配置、结果记录和反馈清单。面向比赛最终交付，还需在昇腾310B上完成OM转换、端到端一致性验证和FPS实测，并根据上板结果确认最终输入预处理和后处理实现。
