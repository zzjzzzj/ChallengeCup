# Agent 结构说明

本文档根据 `docs/关键修正.md` 重新整理 Agent 的项目结构。新的目标不是把所有代码堆在一个目录下，而是把系统拆成三层核心能力：

1. **智能体调度层**：负责训练、推理、二次评估、报告输出和模型版本调度。
2. **持续目标检测模型**：以 YOLOv8n-P2 为基础，加入模态/场景辅助头、软上下文融合和稀疏多专家适配器。
3. **持续学习管理器**：负责旧图回放、旧模型教师、类别-模态原型库、专家锚点巩固和增量任务协议。

## 1. 顶层目录

```text
Agent/
├─ app/                    # 智能体应用层
├─ common/                 # 公共数据结构和工具
├─ configs/                # 模型、任务、实验配置
├─ data/                   # 数据审计、增强、采样
├─ models/                 # YOLO-P2、多专家、辅助头、损失
├─ continual/              # 持续学习管理器
├─ inference/              # 推理、二次检测和结果融合
├─ evaluation/             # 指标、诊断、可视化、报告
├─ deployment/             # ONNX/Ascend 310B导出与测速
├─ scripts/                # 一键脚本
├─ docs/                   # 架构与讲解文档
└─ tests/                  # 单元测试和集成测试
```

## 2. 智能体应用层

```text
Agent/app/
├─ orchestrator/           # 智能体总调度
├─ cli/                    # 命令行入口
└─ reporting/              # JSON报告、可视化报告、讲解材料输出
```

职责：

- 读取配置和任务协议；
- 调用数据准备、训练、推理、评估模块；
- 在推理阶段生成结构化 JSON；
- 在困难样本上触发二次检测；
- 保存模型版本、运行日志和可视化结果。

目标输出格式：

```json
{
  "model_version": "task_3_v2",
  "modality": {"label": "sar", "confidence": 0.98},
  "scene": {"label": "forest", "confidence": 0.94},
  "detections": [
    {
      "class": "soldier",
      "confidence": 0.71,
      "bbox_xyxy": [120, 80, 136, 104],
      "expert_ids": [1, 4],
      "pass": 2
    }
  ],
  "uncertainty": 0.23,
  "second_evaluation_triggered": true,
  "latency_ms": 18.7
}
```

## 3. 公共层

```text
Agent/common/
├─ schemas/                # 数据类和协议结构
└─ utils/                  # 路径、JSON、日志、计时工具
```

职责：

- 定义检测框、任务阶段、样本记录、专家路由结果等统一结构；
- 避免模型层、数据层、推理层各自定义一套不兼容格式。

## 4. 配置层

```text
Agent/configs/
├─ model/                  # YOLOv8n-P2、专家、辅助头、融合强度
├─ tasks/                  # 增量任务顺序
└─ experiments/            # 消融实验配置
```

第一版默认：

```text
检测骨干：YOLOv8n-P2
专家数量：5
专家激活：Top-2
回放库容量：100~200张旧图
增量顺序：IR -> SAR；air/sea -> urban/forest；飞机/轮船 -> 坦克 -> 士兵
```

后续可通过 JSON/YAML 修改增量顺序，不写死在代码中。

## 5. 数据层

```text
Agent/data/
├─ indexing/               # 数据索引和任务划分
├─ quality/                # 图像质量、目标尺度、困难度统计
├─ augmentation/           # 基础增强
├─ copy_paste/             # 目标级Copy-Paste
└─ sampling/               # 困难样本重采样和回放样本打分
```

采样得分：

```text
S_i = α S_rare + β S_uncertain + γ S_hard + δ S_coverage
```

优先保存：

- 士兵样本；
- 困难坦克样本；
- SAR低对比目标；
- 城市和森林复杂背景。

由于已经确认允许保存旧任务图片，回放库第一版采用**图像级回放**，同时保存标签、场景、模态、困难度和历史预测摘要。

## 6. 模型层

```text
Agent/models/
├─ yolo_p2/                # YOLOv8n-P2改造接口
├─ aux_heads/              # 模态头、场景头
├─ experts/                # 稀疏多专家和Top-2路由
├─ prototypes/             # 类别-模态原型库
├─ losses/                 # 检测、蒸馏、原型、锚点损失
└─ adapters/               # 检测logits软上下文融合
```

### 6.1 软上下文融合

关键修正中明确要求不要使用硬规则。最终检测类别 logits 使用：

```text
z_final = z_det + alpha * W_s * p_scene + beta * W_m * p_modality
```

其中：

- `z_det`：YOLO检测头原始类别 logits；
- `p_scene`：场景概率；
- `p_modality`：模态概率；
- `alpha/beta`：辅助信息强度；
- `W_s/W_m`：可学习或配置的投影矩阵。

场景和模态只作为软辅助，不直接覆盖检测类别。

### 6.2 稀疏多专家

第一版不使用12个类别绑定专家，而使用 5 个潜在角色专家：

```text
shared_stable_expert
ir_texture_expert
sar_scatter_expert
small_object_expert
complex_background_expert
```

路由输入：

```text
q = [GAP(F), p_modality, p_scene, r]
```

其中 `r` 包括目标尺度、图像质量和不确定性统计。

每层只激活 Top-2 专家：

```text
F_out = F + sum(g_e * E_e(F)), e in TopK(g)
```

专家不预先绑定类别，学习潜在分布和困难模式。

### 6.3 类别-模态原型

面向非配对 IR/SAR 数据，维护目标级类别-模态原型：

```text
P_{class, modality}
```

再构造类别共享原型：

```text
J_class = weighted_average(P_{class, ir}, P_{class, sar})
```

训练时目标特征对齐到共享类别原型，但保留模态私有残差，避免把 IR 和 SAR 强行压成完全相同的表示。

## 7. 持续学习层

```text
Agent/continual/
├─ manager/                # ContinualLearningManager
├─ protocols/              # 增量任务协议
├─ replay/                 # 图像回放库
├─ distillation/           # 教师模型与检测响应蒸馏
├─ anchors/                # 专家锚点软巩固
└─ versioning/             # 模型版本和任务状态
```

增量训练损失：

```text
L_t = L_det
    + λ_KD L_KD
    + λ_feat L_feat
    + λ_proto L_proto
    + λ_rel L_rel
    + λ_anchor L_anchor
```

第一版实现优先级：

1. 图像回放；
2. 旧模型教师引用；
3. 分类/定位响应蒸馏；
4. P2/P3目标区域特征蒸馏；
5. 类别-模态原型；
6. 专家锚点软巩固。

## 8. 推理与二次评估层

```text
Agent/inference/
├─ pipeline/               # 单图/批量推理流程
├─ uncertainty/            # 不确定性U(x)
├─ cascade/                # 二次检测触发器
├─ slicing/                # 2x2/3x3重叠切片
└─ fusion/                 # NMS/WBF结果融合
```

不确定性：

```text
U(x) = α H(p_cls)
     + β (1 - p_max)
     + γ D_expert
     + δ D_scene
```

触发二次检测条件：

- 没有检测框；
- 只检测到低置信度士兵；
- 士兵目标非常小；
- 专家结果差异明显；
- 场景头与检测头严重冲突；
- `U(x) > threshold`。

二次检测内容：

- 原图 2x2 或 3x3 重叠切片；
- 局部高分辨率检测；
- 调用微小目标专家；
- 适当降低士兵阈值；
- 融合一次和二次检测结果。

## 10. 推荐开发顺序

第一阶段：建立可持续学习的完整架构。

```text
任务协议
-> 图像回放库
-> 旧模型教师管理
-> 软上下文融合
-> 不确定性二次检测
-> JSON报告
```

第二阶段：先解决士兵检测。

```text
YOLOv8n baseline
-> YOLOv8n-P2
-> 士兵困难样本重采样
-> 目标级Copy-Paste
-> 自适应切片二次检测
```

第三阶段：持续检测。

```text
IR -> SAR
air/sea -> urban/forest
飞机/轮船 -> 坦克 -> 士兵
```

第四阶段：稀疏多专家和原型库。

```text
5专家Top-2路由
专家锚点软巩固
类别-模态原型
共享/私有表示分解
```

第五阶段：端侧部署与优化。

```text
ONNX
-> ATC
-> OM
-> FPS/精度核对
```

## 11. 迁移旧代码的原则

现有 `Agent/*.py` 已经能跑通基础智能体，不应一次性全部移动。建议：

1. 先在新目录中实现新组件；
2. 保留旧 CLI 入口；
3. 用适配器把旧入口逐渐接到新组件；
4. 每迁移一个模块就跑一次单元测试和一张样本推理；
5. 等新结构稳定后，再删除或重定向旧文件。

这样能避免“架构变漂亮了，但原本能跑的流程断掉”。
