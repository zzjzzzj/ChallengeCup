# 四类到六类多批次小样本增量训练

## 目的与旧协议差异

本协议以四类顺序 `soldier`、`small_aircraft`、`warship`、`tank` 的本地 checkpoint 为阶段 0，扩展为固定六类头：追加 `patrol_boat`、`armored_vehicle`。它与旧的六阶段 Class-IL 不同：旧协议每阶段只引入一个固定类别；本协议允许任意批次数，每批是六类的任意非空子集，可以缺类，也可以在多个批次重复请求同一类。计划整体必须覆盖两个新增类。

所有数据、checkpoint、回放池和产物均为本地文件。新流程不会上传数据，也不会在 dry-run 或 plan-only 中导入 Ultralytics 或联网。一键编排生成的两个训练命令显式带 `--no-amp`，因为 Ultralytics 的 AMP 自检可能尝试加载 `yolo26n.pt`；如需独立命令严格保持不联网，也应带上 `--no-amp`。

## 分步命令

下面命令使用仓库相对路径示例；请把 `data/base_raw.yaml`、`data/increment_raw.yaml` 和 `models/local_initial.pt` 替换为本地文件。

### 1. 离线增广

```powershell
python train.py augment-yolo --data data/base_raw.yaml --output artifacts/base_augmented --default-modality ir
python train.py augment-yolo --data data/increment_raw.yaml --output artifacts/increment_augmented --default-modality ir
```

输入 YAML 的 `train` 可以是目录或 txt 清单。默认保留 train 原图并生成三种确定性 IR/SAR 变体；`val` 和 `test` 只复制原图，不增广。输出包含 `data.yaml`、`augmentation_manifest.csv` 和 `augmentation_summary.json`。输出目录必须为空或不存在。

### 2. 计划与 K-shot

显式计划文件示例 `configs/batch_plan.json`：

```json
{
  "batches": [
    {"id": "batch_01", "classes": ["soldier", "small_aircraft", "patrol_boat"]},
    {"id": "batch_02", "classes": ["warship", "patrol_boat"]},
    {"id": "batch_03", "classes": ["tank", "armored_vehicle"]}
  ]
}
```

`--max-current-images-per-class K` 是每批每类 current 图像上限；不传时使用该 source group 分配到该批的全部图像。分配优先 source 多样性，并确保同一 source 的原图与离线变体不会跨批。每类 source group 在整个计划中只消费一次。

```powershell
python train.py prepare-batch-il `
  --base-data artifacts/base_augmented/data.yaml `
  --increment-data artifacts/increment_augmented/data.yaml `
  --output artifacts/batch_il_prepared `
  --num-batches 3 `
  --batch-plan configs/batch_plan.json `
  --max-current-images-per-class 8 `
  --buffer-size 200 `
  --buffer-size 500 `
  --seed 42
```

不传 `--batch-plan` 时，程序按 seed、类别和 source group 确定性分到 `N` 个批次。base train 是第一批非空 replay 来源；之后每个 buffer 都从 base train 加上已消费增量 current 按已见类重平衡。buffer 容量只允许 200 或 500。

每批 YAML 始终声明完整六类 `nc=6/names`，但 train/val/test 标签只包含 base 四类和截至该批已见的新增类。val 来自 increment 固定留出并用于选模；test（若提供）只在所有批次完成后评估。

### 3. ER/DER 训练

```powershell
python train.py batch-il-yolo `
  --prepared artifacts/batch_il_prepared `
  --initial-checkpoint runs/base_four/weights/best.pt `
  --method der `
  --buffer-size 200 `
  --output runs/batch_il_der_200 `
  --epochs 30 `
  --device cpu `
  --no-builtin-aug `
  --no-amp
```

真实训练严格要求 `--initial-checkpoint` 是本地四类 checkpoint，且 checkpoint 的 `names` 必须精确等于四类顺序。第一批 ER/DER 都从四类 checkpoint 开始；第一批 DER 的 teacher 是四类 checkpoint，student 是六类头，回放 teacher target 只作用于 replay 图像。每批使用上一批 `best.pt` 作为下一批输入。

`--method er` 使用监督回放；`--method der` 使用现有 DarkReplayModel 的分类/框响应蒸馏。val 选出每批 `best.pt`，最终报告六类 AP、seen 类均值、present/missing、首次到达批次、按批矩阵、遗忘和 BWT。test 不参与选模。

Sparse-MoE 可在同一命令追加现有参数，例如：

```powershell
python train.py batch-il-yolo --prepared artifacts/batch_il_prepared --initial-checkpoint runs/base_four/weights/best.pt --method der --buffer-size 500 --output runs/batch_il_sparse_500 --sparse-moe --expert-count 5 --top-k 2 --expert-bottleneck 0.25 --router-hidden 128 --aux-hidden 128 --anchor-rho 0.95 --no-builtin-aug --no-amp
```

## 一键编排与审计

`four-to-six-yolo` 按顺序执行：base augment → 现有四类 YOLO 训练（关闭 built-in aug）→ increment augment → prepare-batch-il → batch-il-yolo。它拒绝覆盖非空 workspace。

先只审计命令和协议，不训练、不联网：

```powershell
python train.py four-to-six-yolo `
  --base-data data/base_raw.yaml `
  --increment-data data/increment_raw.yaml `
  --generic-model models/local_initial.pt `
  --workspace artifacts/four_to_six_plan `
  --num-batches 3 `
  --batch-plan configs/batch_plan.json `
  --method der `
  --buffer-size 200 `
  --max-current-images-per-class 8 `
  --base-epochs 30 `
  --increment-epochs 30 `
  --device cpu `
  --dry-run
```

去掉 `--dry-run` 才会实际创建 workspace 并运行五步。实际产物位于 workspace 子目录：`base_augmented`、`runs/base_four`、`increment_augmented`、`prepared_batch_il` 和 `runs/batch_il_<method>_<buffer>`。

## 产物、隐私与检查

- 增广：`data.yaml`、`augmentation_manifest.csv`、`augmentation_summary.json`。
- 准备：`batch_incremental_dataset_summary.json`，每批固定六类 YAML、current/replay/val/test 清单、buffer before/after JSON、context index。
- 训练：`batch_incremental_training_summary.json`、每批 stage summary、每批 `best.pt`、最终模型和指标矩阵。
- 运行前确认数据与 checkpoint 位于本机；脚本默认 `YOLO_OFFLINE=true`，不下载权重、不上传数据。
- 建议先运行 `--dry-run`，再用临时合成数据执行 augment → prepare → trainer dry-run。
- 旧命令 `prepare-class-il` / `class-il-yolo` 的六阶段行为保持不变；新命令只读取新 `scenario=batch_class_incremental` 协议。
