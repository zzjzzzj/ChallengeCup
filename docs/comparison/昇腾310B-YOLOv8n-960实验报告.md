# 昇腾 310B 部署候选：YOLOv8n-960 实验报告

## 一、结论

首轮部署友好策略选择 **标准 YOLOv8n + 960 静态输入 + 增广集 + COCO 预训练**，没有采用 YOLOv10、自定义 P2 检测头或图内 NMS。原因是标准 YOLOv8 算子链成熟，便于导出 ONNX 并由华为 ATC 转换为 OM。

实验结果支持保留该方案作为 310B 的高精度候选：

- 同口径 mAP@0.5：85.25% -> **87.89%**，提升 **2.64 个百分点**。
- 同口径 mAP@0.5:0.95：40.86% -> **44.47%**，提升 **3.61 个百分点**。
- soldier mAP@0.5：51.24% -> **60.10%**，提升 **8.85 个百分点**。
- Recall：86.23% -> **90.22%**，提升 **3.99 个百分点**。
- Precision：79.07% -> **77.09%**，下降 **1.98 个百分点**。

因此，960 输入有效改善了当前最难的 soldier 小目标和严格定位指标，代价是计算量增加以及误检略有上升。

## 二、实验设置

| 项目 | 设置 |
|---|---|
| 模型 | YOLOv8n 标准检测模型 |
| 训练数据 | 增广集 4400 张 |
| 验证集 | 79 张，仅用于选最佳检查点 |
| 测试集 | 76 张，仅用于最终汇报 |
| 输入尺寸 | 960×960 |
| 预训练 | COCO `yolov8n.pt` |
| Batch Size | 8 |
| 最大轮数 | 50 |
| Early Stopping | patience=10 |
| 实际完成轮数 | 27 |
| 最佳严格 mAP 轮次 | 第 17 轮 |
| 随机种子 | 42 |
| GPU | NVIDIA RTX 4060 Laptop 8GB |

原始测试图分辨率为 640×512；soldier 真实框中位尺寸约为 9×12 像素，最小宽度约 5 像素。升到 960 后，目标在网络输入中的中位尺寸约变为 13.5×18 像素。

## 五、算子兼容性检查

ONNX 图共 232 个节点，算子如下：

`Add、Concat、Conv、Div、MaxPool、Mul、Reshape、Resize、Sigmoid、Slice、Softmax、Split、Sub、Transpose`。

这些均为常见 ONNX 标准算子，当前图中没有自定义算子、图内 NMS、NonMaxSuppression 或 YOLOv10 的端到端/NMS-free 特殊后处理节点。从模型图角度看，比直接切换 YOLOv10 更适合作为 310B 首个部署版本。

## 六、310B 转换命令

本机没有安装昇腾 ATC，因此已经完成 ONNX 验证，但尚未生成 OM。需要在安装 CANN 的昇腾环境执行：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh

atc \
  --model=detector_yolov8n_bs1.onnx \
  --framework=5 \
  --output=detector_yolov8n_960_bs1 \
  --input_format=NCHW \
  --input_shape="images:1,3,960,960" \
  --precision_mode=allow_fp32_to_fp16 \
  --soc_version=Ascend310B4
```

`Ascend310B4` 只是示例。实际值必须通过 `npu-smi info` 和 `atc --list_soc_version` 确认，可能是 Ascend310B1、Ascend310B4 等。

## 七、310B 预处理与后处理约定

### 预处理

1. 按 Ultralytics letterbox 规则缩放并补边到 960×960。
2. BGR 转 RGB。
3. `uint8` 转 `float32`，除以 255。
4. HWC 转 CHW。
5. 增加 batch 维度，最终形状 `[1,3,960,960]`。

### 后处理

ONNX 输出为 `[1,8,18900]`：4 个框坐标通道加 4 个类别分数通道。NMS 不在模型图内，需要在 CPU 或昇腾应用侧完成：

- 初始置信度阈值：0.25。
- NMS IoU 阈值：0.70。
- 将网络坐标按 letterbox 的缩放比例和补边量映射回原图。

阈值仍应在 79 张验证集上进一步选择，不能用测试集调参。

## 八、部署决策

建议保留两个 OM 配置：

| 配置 | 用途 |
|---|---|
| YOLOv8n-640 batch=1 | 低延迟兜底版本 |
| YOLOv8n-960 batch=1 | 当前高精度推荐版本 |

是否最终采用 960，取决于 310B 实测 FPS。960 的输入像素数是 640 的 2.25 倍，理论计算和内存访问都会显著增加。必须在设备上完成以下测试：

1. OM 转换是否成功。
2. 100 次以上预热后单张延迟、P50/P95 延迟和 FPS。
3. OM 输出经过同一后处理后的 76 张测试集精度。
4. FP16 与后续 INT8 量化的精度差。

若 960 达不到实时要求，优先回退到 640；不要立即换 YOLOv10。第二阶段可以考虑 800/832 静态输入，寻找精度与速度的折中。
